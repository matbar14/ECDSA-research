## Найденные и исправленные ошибки

### 1. `phase_difference_experiment.py`: отсутствующая функция в `2edcl.py`

Эксперимент вызывал `inversion.reconstruct_points_from_lambda(...)`, но такой
функции в `2edcl.py` не было — были только отдельные шаги цепочки
(`derive_polynomial_equation` -> `solve_quadratic_mod_p` ->
`find_points_on_curve` -> `verify_lambda_values`) с диагностическим выводом.
Эксперимент падал с `AttributeError` на первом же сэмпле.

Исправление: в `2edcl.py` добавлена тихая составная функция
`reconstruct_points_from_lambda(target_lambda)`, которая решает квадратное
уравнение по `x_P`, строит точки кривой и возвращает кандидатов объектами
`EllipticCurvePoint`. Отдельно обработано граничное соглашение `Lambda = 0`
из `w1.py`: проверяются корни знаменателя `x = beta*x_G` и `x = x_G/beta`,
плюс корень числителя `x = 0`.

Контроль после исправления: на 200 независимых скалярах — 91 набор из двух
кандидатов и 109 из четырёх (совпадает с пропорцией README 49.8%/50.2%),
исходная точка отсутствует 0 раз. Полный прогон: 10000/10000 сэмплов,
фазовая подпись `(d01, d12)` сужает четыре кандидата ровно до двух
(`P` и `-P`) во всех случаях.

### 2. `eng_bsgs.cpp`: `parse_u64` принимал отрицательные числа

`strtoull("-1")` молча возвращает `ULLONG_MAX`, поэтому `--size -5`,
`--segment -1`, `--baby-rows -3` принимались как валидные огромные значения
и приводили к попытке выделить гигантскую таблицу. Исправление: отказ входов
с `+`, `-`, пробелом и табуляцией; теперь такие аргументы дают `usage`-ошибку
с кодом 2. Проверено на пяти отрицательных входах.

### 3. `eng_bsgs.cpp`: невыровненная запись `uint64_t`

`point_key` и `invariant_key` писали 32 байта ключа прямо в `raw.data()+1`
33-байтового массива — `uint64_t`-записи по невыровненному адресу (UB, ловится
UBSan, потенциальная проблема переносимости). Исправление: выровненный
стековый буфер `alignas(8)` + `memcpy` в оба места. После правки UBSan не
показывает ни одного отчёта о невыровненном доступе.

## Замечено, но не менялось

- Подписанные переполнения в `secp256k1/IntMod.cpp` (обратное по Монтгомеру)
  — намеренная арифметика с заворачиванием в коде keyhunt, работает на
  gcc/x86-64; это унаследованная библиотека, поведение совпадает с upstream.
- Счётчик `unique baby rows built` в `eng_bsgs.cpp` всегда равен сырому
  числу строк: дедупликация ключей фактически не считается (в GLV-режиме
  дубликаты K3 в таблице намеренны). Косметика метрики.
- Makefile-цель `eng_bsgs` не отслеживает зависимости от заголовков:
  после правки `.cpp` нужна явная пересборка (`rm -f eng_bsgs && make eng_bsgs`).
