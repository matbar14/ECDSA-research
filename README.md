# Орбитальные инварианты на secp256k1

## Аннотация

В репозитории находится исследовательский расчёт для кривой secp256k1

```text
y^2 = x^3 + 7 (mod p)
```

со стандартной базовой точкой `G` простого порядка `n`. Для скаляра `k`
скрипт строит `P = kG`, применяет эндоморфизм порядка три

```text
phi(x, y) = (beta*x, y) (mod p),
```

и вычисляет инвариант `Lambda` крест-отношенческого типа на орбите

```text
{P, phi(P), phi^2(P)}.
```

Основной алгебраический результат имеет вид

```text
Lambda(P) + Lambda(phi(P)) + Lambda(phi^2(P)) = 0 (mod p),
```

во всех точках, где определены три значения инварианта.

## Параметры

Расчёт использует стандартные простое поле и порядок группы secp256k1:

```text
p = FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEFFFFFC2F
n = FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141
```

`beta` является нетривиальным кубическим корнем единицы, используемым
эндоморфизмом secp256k1. В поле `F_p` выполняются соотношения

```text
beta^3 = 1
beta^2 + beta + 1 = 0.
```

Скрипт вычисляет и выводит обе конгруэнции для используемой константы.

## Определения

Для `P = (x_P, y_P)` и `G = (x_G, y_G)` определим

```text
Lambda(P) =
  ((x_G - beta*x_G) * (x_P - beta*x_P)) /
  ((x_G - beta*x_P) * (x_P - beta*x_G)) (mod p).
```

Деление означает умножение на обратный элемент в `F_p`. Следовательно,
кросс-отношение алгебраически не определён, если его знаменатель равен нулю.
В реализации `w1.py` для такого граничного случая явно принято соглашение
`Lambda(P) = 0`, а значит угол первого радиуса равен `0`. Это соглашение
геометрической модели, а не результат деления в `F_p`.

## Прямое назначение угла приватному скаляру

Для каждого приватного скаляра `k` строится `P = kG`, затем по формуле
выше вычисляется канонический остаток

```text
a(k) = Lambda(P),  0 <= a(k) < p.
```

Этот остаток задаёт точку на единичной окружности и угол первого радиуса:

```text
theta(k) = 2*pi*a(k)/p.
```

Скрипт [private_angle_experiment.py](private_angle_experiment.py) проверяет
это прямое отображение на различных 256-битных приватных скалярах. Повторы
проверяются по точному остатку `a(k)`, а не по числу с плавающей точкой для
угла; остатки также группируются по 256 равным дугам окружности.

```bash
python3 private_angle_experiment.py
```

На 100 000 различных 256-битных скаляров в четырёх пакетах по 25 000 (зерна
`20261014`--`20261017`) получено:

| Проверка | Результат |
| --- | ---: |
| Точные индексы угла `a(k)` | 100 000 |
| Точные повторы индекса угла | 0 |
| Заполнение 256 равных дуг | 341--442 |
| Pearson `chi^2` распределения по дугам | `249.354240` |

Значение `chi^2` близко к ожидаемому среднему `255` для 255 степеней свободы,
поэтому эта выборка согласуется с равномерным распределением индексов угла
по окружности.

## Квантование первого угла для диапазонной таблицы

Для известного диапазона приватных скаляров угол первого радиуса можно
квантовать в `b` бит без перехода к вещественной арифметике:

```text
q_b(k) = floor(2^b * Lambda(kG) / p),  0 <= q_b < 2^b.
```

Это номер равной угловой ячейки на окружности. Предварительная таблица
`q_b -> k` или `q_b -> список k` сокращает исходный диапазон до содержимого
соответствующей ячейки.

Скрипт [angle_quantization_experiment.py](angle_quantization_experiment.py)
строит такую таблицу для непрерывного диапазона 256-битных скаляров и
измеряет ожидаемое число кандидатов после поиска по квантованному углу.

```bash
python3 angle_quantization_experiment.py
```

На диапазоне из 100 000 последовательных скаляров, начиная с `2^255`,
получены:

| Битов угла | Непустых ячеек | Размер ячейки | Одиночных ключей | Среднее число кандидатов |
| ---: | ---: | ---: | ---: | ---: |
| 8 | 256 | 349--447 | 0 | 391.651200 |
| 12 | 4 096 | 9--46 | 0 | 25.438040 |
| 16 | 51 166 | 1--9 | 21 604 | 2.534760 |
| 20 | 95 359 | 1--5 | 90 878 | 1.096120 |

Таким образом, в этой таблице 20-битное квантование первого угла делает
однозначной ячейку для `90.878%` значений диапазона; остальные требуют
проверки небольшого списка кандидатов из той же ячейки.

## Якорная таблица: восстановление через «угол + смещение»

Отдельная гипотеза состоит в том, чтобы не хранить полный скаляр `k` в
таблице, а представить его как

```text
k = anchor + offset.
```

Квантованный угол используется как fingerprint для выбора ячейки, `anchor` —
как начало локального блока, а `offset` — как короткое смещение внутри этого
блока. Такая схема экономит место только тогда, когда совпадения одной
угловой ячейки действительно локальны по числовой оси скаляров.

Скрипт [angle_anchor_experiment.py](angle_anchor_experiment.py) измеряет это
условие на последовательном диапазоне. Он сравнивает одну квантованную
координату и пару
`(Lambda(P), Lambda(phi(P)))`, затем сообщает охват ячеек и долю одиночных
смещений:

```bash
python3 angle_anchor_experiment.py \
  --range-size 2000 \
  --block-size 100 \
  --bits 8 12 16
```

Контрольный запуск на окне из 2000 скаляров дал:

| Биты на координату | Ключ | Средний охват ячейки | Одиночные смещения |
| ---: | --- | ---: | ---: |
| 8 | одна `Lambda` | 75.533% окна | 0.050% |
| 12 | одна `Lambda` | 9.244% окна | 58.400% |
| 16 | одна `Lambda` | 0.770% окна | 96.200% |
| 8 | пара `Lambda` | 0.569% окна | 96.800% |
| 12 | пара `Lambda` | 0.079% окна | 99.900% |
| 16 | пара `Lambda` | 0.050% окна | 100.000% |

Пара углов резко уменьшает число кандидатов в небольшой проверенной выборке,
поэтому она подходит для компактного fingerprint и последующего точного
пересчёта. Однако это ещё не является глобальной формулой восстановления
`k`: на существенно большем диапазоне совпадения одной ячейки могут лежать
далеко друг от друга. Именно локальность, а не только равномерность углов,
определяет, можно ли хранить короткий `offset`.

### Проверка глобальной локальности на окне `2^135`

Чтобы не делать вывод только по последовательным локальным скалярам, скрипт
[angle_global_locality_experiment.py](angle_global_locality_experiment.py)
выбирает `k` равномерно по широкому окну и измеряет размах повторяющихся
ячеек. Для каждой ячейки вычисляются:

```text
span = max(k) - min(k) + 1
offset_bits = ceil(log2(span)).
```

Пример запуска:

```bash
python3 angle_global_locality_experiment.py \
  --samples 20000 \
  --width-bits 135 \
  --bits 8 12
```

Результат на 20 000 равномерно выбранных скалярах:

| Биты | Ключ | Повторяющихся ячеек | Средний `span` | `span <= 1%` | `span <= 5%` | Средний `offset_bits` |
| ---: | --- | ---: | ---: | ---: | ---: | ---: |
| 8 | одна `Lambda` | 20 000 | 97.381% окна | 0.000% | 0.000% | 135.00 |
| 8 | пара углов | 2 590 | 34.968% окна | 1.313% | 8.225% | 133.44 |
| 12 | одна `Lambda` | 3 906 | 62.759% окна | 0.071% | 0.534% | 134.58 |
| 12 | пара углов | 14 | 32.938% окна | 0.000% | 7.143% | 133.43 |

Редкие удачные коллизии действительно бывают: для 8-битной пары минимальный
измеренный размах повторившейся ячейки составил `0.004%` окна, а для 12-битной
пары — `4.878%`. Поэтому такой шанс можно использовать как вероятностный
фильтр или как многоступенчатую процедуру:
сначала найти ячейку, затем проверить её точный `Lambda` и только после этого
строить локальный якорь. Нельзя заранее считать, что любая коллизия даст
короткий `offset`.

Для пары углов при 12 битах большинство ячеек в этой разреженной выборке
одиночны, но повторяющиеся ячейки имеют глобальный размах порядка третьей
части всего окна, а не короткий локальный блок. Следовательно, квантование
может быть хорошим fingerprint-фильтром, но на этом тесте не подтверждает
схему `k = anchor + короткий offset` для глобального диапазона `2^135`.
Это измеренный результат по широкой выборке, а не предположение о невозможности
такой схемы вообще.

### Проба случайного 135-битного ключа

Скрипт [random_135bit_recovery_experiment.py](random_135bit_recovery_experiment.py)
генерирует случайный `k` в окне `[2^134,2^135)`, строит публичную точку и
проверяет, попадает ли её квантованная угловая ячейка в разреженную таблицу:

```bash
python3 random_135bit_recovery_experiment.py \
  --samples 5000 --bits 8 12 16 20 --key pair \
  --seed 20260925 --exclude-target
```

В контрольном запуске ключ был

```text
k = 0x58df7a07661c4b2b82012c0179cddba0b3
P = 03df86b7c1cee6ba3dd6127bc82225033a21cd01ae8fff503f13b74bfc72c0d76e
```

При двухугловом ключе ни одна из ячеек `8, 12, 16, 20` бит не содержала
случайную цель в таблице из 5000 других скаляров. Это ожидаемо: такая таблица
покрывает лишь ничтожную долю пространства `2^135`. Запуск без
`--exclude-target` подтверждает только механизм lookup (цель намеренно
добавляется в таблицу), но не заменяет полное покрытие диапазона.

### Полный тест на конечном диапазоне с параллельной сборкой

Чтобы проверить именно восстановление из таблицы, добавлен
[parallel_angle_table_recovery.py](parallel_angle_table_recovery.py). Он
покрывает каждое `k` в заданном тестовом диапазоне, строит компактный
двухугловой fingerprint в нескольких процессах, сохраняет таблицу на диск,
а затем выбирает случайную публичную точку и выполняет отложенную точную
проверку кандидатов.

Пример для 32 процессов:

```bash
python3 parallel_angle_table_recovery.py \\
  --bit-length 135 \\
  --range-size 100000 \\
  --bits 16 \\
  --workers 32 \\
  --chunk-size 1000 \\
  --output /tmp/angle_table.bin
```

На контрольном запуске диапазона из 10 000 скаляров таблица заняла 160 024
байта, fingerprint-ячейка цели содержала одного кандидата, точная проверка
вернула исходный offset и дала `recovery correct: True`. Это end-to-end тест
схемы «покрыть диапазон → найти ячейку → пересчитать точные углы». Прямое
масштабирование до `2^135` всё равно требует полного покрытия этого диапазона;
эксперимент измеряет механику и рост коллизий на конечном окне.

Сохранённую таблицу можно загрузить и проверить по внешнему compressed public
key без повторной сборки:

```bash
python3 parallel_angle_table_recovery.py \
  --load-table angle_table_100k_12.bin \
  --target-public-key 02... \
  --queries 1 --workers 1 --chunk-size 1 --range-size 1 --bits 12
```

Параметры `--workers`, `--chunk-size`, `--queries`, `--range-size` и `--bits`
при режиме `--load-table` используются только для совместимости CLI; диапазон
и число бит берутся из заголовка файла.

Опция `--bit-length 135` задаёт начало окна `2^134`, то есть все записи имеют
действительно 135-битные скаляры. Без этой опции по умолчанию используется окно
от `2^255` для 256-битного теста.

### Локальность ячеек для kangaroo

Малое число кандидатов в ячейке само по себе не означает, что оно задаёт
короткий интервал для алгоритма Pollard kangaroo. Для каждой ячейки `j`
скрипт также измеряет её скалярный охват:

```text
W_j = max{k : q_b(k) = j} - min{k : q_b(k) = j} + 1.
```

Для применения kangaroo необходимо, чтобы `W_j` был значительно меньше
исходного диапазона. Эксперимент на 30 000 последовательных 256-битных
скалярах, начиная с `2^255`, дал следующие результаты:

| Битов угла | Среднее число кандидатов | Средний охват для запроса | Средний охват ячеек с коллизиями | Максимальный охват |
| ---: | ---: | ---: | ---: | ---: |
| 8 | 118.196067 | 98.3169% | 98.2953% | 99.9200% |
| 12 | 8.318933 | 76.3522% | 73.1832% | 99.8200% |
| 16 | 1.467600 | 13.9504% | 36.1464% | 98.4967% |
| 20 | 1.028267 | 0.9332% | 33.3502% | 96.3400% |

При 20 битах большинство ячеек на этой небольшой выборке одиночны, поэтому
их ширина формально равна одному скаляру. Для неодиночных ячеек средний
охват всё ещё равен `33.3502%`, а максимум — `96.3400%` диапазона. При 8 и
12 битах, где ячейки содержат много точек, значения `k` почти покрывают
весь исходный интервал. В этой выборке квантование уменьшает число
кандидатов, но не создаёт узкий непрерывный интервал, необходимый для
ускорения kangaroo.

### Цифры и биты нормированной фазы

Скрипт [phase_digit_bit_experiment.py](phase_digit_bit_experiment.py)
исследует не вещественное приближение угла, а точное рациональное число

```text
r_k = Lambda(kG) / p,  0 <= r_k < 1.
```

Его `i`-я десятичная цифра и `i`-й двоичный бит вычисляются целочисленно:

```text
digit_10(i) = floor(10^i * Lambda(kG) / p) mod 10,
bit_2(i)    = floor(2^i  * Lambda(kG) / p) mod 2.
```

```bash
python3 phase_digit_bit_experiment.py
```

Опциональные параметры `--samples`, `--decimal-positions`,
`--binary-positions` и `--offset-bits` меняют объём эксперимента без
изменения исходного кода. Проверочный запуск на 30 000 последовательных
скалярах проверил первые восемь десятичных и первые 16 двоичных позиций.
Значения chi-square десятичных цифр лежали в диапазоне `5.850000..13.834000`
при девяти степенях свободы; доли единиц двоичных позиций —
`49.3633%..50.5500%`; совпадения с одноимёнными младшими битами смещения —
`49.7167%..50.6700%`. Эта выборка не выявила простой побитовой связи. Она
не исключает более сложную зависимость и задаёт воспроизводимый тест для
следующих гипотез.

## Восстановление из диапазонной угловой таблицы

Скрипт [angle_table_recovery_experiment.py](angle_table_recovery_experiment.py)
реализует полный поиск по заранее вычисленной таблице известного диапазона.
Для каждой записи таблица хранит

```text
q_20 = floor(2^20*Lambda(kG)/p)
```

и точный остаток `Lambda(kG)`. При запросе скрипт получает только публичную
точку `P`, вычисляет её угловую ячейку, выбирает список из этой ячейки и
сопоставляет точный индекс угла.

```bash
python3 angle_table_recovery_experiment.py
```

Проверка на непрерывном диапазоне из 25 000 256-битных скаляров, начиная с
`2^255`, дала:

| Проверка | Результат |
| --- | ---: |
| Использованных 20-битных ячеек | 24 705 |
| Среднее число кандидатов после ячейки | `1.023840` |
| Восстановленных `k` по публичной точке | 25 000 / 25 000 |
| Запросов с единственным точным индексом угла | 25 000 / 25 000 |

Это эксперимент восстановления внутри заранее покрытого диапазона: размер
таблицы растёт вместе с диапазоном, а точный индекс угла используется как
вторичная проверка кандидатов из квантованной ячейки.

Скрипт также называет пару

```text
(x_P^3, y_P)
```

"координатами тора" и выводит несколько производных величин поля. Это
алгебраические дескрипторы данного эксперимента, а не стандартное евклидово
вложение тора.

## Вывод орбитального тождества

## C7 и факторизация по GLV-орбитам

Термин `C7` в данном контексте относится к специальной форме secp256k1

```text
y^2 = x^3 + 7 (mod p),
```

а не к новому классу сложности задачи дискретного логарифмирования. У этой
кривой есть эндоморфизм Галланта--Ламберта--Ванстоуна порядка три:

```text
phi(x, y) = (beta*x, y),       beta^3 = 1,
```

и для базовой точки выполняется `phi(P) = lambda*P` в группе скаляров.
Вместе с инволюцией `P -> -P` он порождает шесть симметрий

```text
{+1, -1, +lambda, -lambda, +lambda^2, -lambda^2}.
```

Поэтому точки

```text
P, phi(P), phi^2(P), -P, -phi(P), -phi^2(P)
```

образуют одну GLV-орбиту. Для неё естественны инварианты

```text
K3(P) = x(P)^3 (mod p)
K (P) = min(y(P), p - y(P)).
```

Первый инвариант не меняется при умножении `x` на `beta`, а второй устраняет
знак точки. Таким образом, они описывают орбиту, но намеренно забывают
положение точки внутри неё. Это отличается от ориентированного значения
`Lambda(P)`, используемого в экспериментах выше.

### Что даёт орбитное представление

В BSGS одну запись можно хранить для всей шеститочечной орбиты. В идеальной
модели это уменьшает число представителей до

```text
W6(n) = ceil(2*sqrt((n - 1)/6)),
```

то есть даёт постоянный выигрыш примерно `sqrt(6)` по сравнению с обычной
оценкой `2*sqrt(n - 1)`. Это экономия памяти и групповых операций, а не
изменение корневой зависимости от размера группы.

Для GPU-поиска иногда предлагают хранить только короткий отпечаток
`K3` (например, несколько десятков бит), а точную запись восстанавливать
после редкого совпадения. Такая схема deferred fingerprint/lattice recovery
может быть полезной инженерной оптимизацией, однако в этом репозитории она
не реализована и приведённые здесь эксперименты не являются её бенчмарком.
При распределении работы между несколькими GPU маршрутизация должна
использовать `K3(T) mod G`, а не обычный `x(T) mod G`: иначе представители
одной орбиты могут попасть на разные устройства.

### Ограничения

* На коротком интервале скаляров GLV-партнёры обычно лежат далеко друг от
  друга. Если ширина окна существенно меньше `2^128`, внутри него остаётся
  в основном только знаковая пара `P, -P`; дополнительное трёхкратное
  сжатие не превращается в такой же выигрыш для Pollard kangaroo.
* Перенос орбитального инварианта на случайные блуждания требует отдельного
  анализа. Неподходящее фактор-отображение может разбить функциональный граф
  на бассейны с терминальными циклами и уменьшить вероятность коллизии.
* Даже идеальное использование шести симметрий даёт лишь постоянный
  множитель (`sqrt(6)` или `sqrt(3)`). Для полного пространства secp256k1
  остаётся порядок `2^128` групповых операций; субкорневого алгоритма это не
  даёт.

Следовательно, `C7`/GLV полезен как способ факторизовать представление и
сократить константы в таблицах, но не как способ восстановить приватный
скаляр из одного из перечисленных инвариантов. В частности, `K3` и `K`
обратны обычно нескольким точкам орбиты, тогда как точные фазовые подписи в
предыдущих разделах восстанавливают лишь публичную точку (с неизбежной
парой `P, -P`), а не её дискретный логарифм.

### Проверка именно этих инвариантов

Для воспроизводимой проверки добавлен скрипт
[c7_invariant_experiment.py](c7_invariant_experiment.py). Он для случайных
`P = kG` проверяет соответствие `phi(P) = [lambda]P`, строит все шесть точек
GLV-орбиты и считает число различных значений каждого ключа внутри орбиты:

```bash
python3 c7_invariant_experiment.py --samples 1000 --seed 20260925
```

Ожидается один класс для `K3 = x^3` и для пары
`(K3, min(y,p-y))`; это и есть проверка их шестикратной инвариантности.
`Lambda(P)` в текущем определении ориентирован по циклу `phi`, поэтому его
значения обычно образуют три значения (каждое повторяется для `P` и `-P`) и
не являются тем же самым ключом, что `K3`.

Если цель — именно таблица углов, используйте
[c7_angle_table_recovery.py](c7_angle_table_recovery.py):

```bash
python3 c7_angle_table_recovery.py --orbits 1000 --seed 20260925
```

Здесь ключ строки — точная неупорядоченная тройка
`sort(Lambda(P), Lambda(phi(P)), Lambda(phi^2(P)))`, а значение строки —
шесть скаляров
`{±k, ±lambda*k, ±lambda^2*k} (mod n)`. Поэтому таблица действительно
восстанавливает GLV-орбиту из публичной точки `P`, но не выделяет единственный
ориентированный `k`. В тесте на случайных независимых орбитах число строк
сжимается ровно в шесть раз; если известный диапазон содержит только одного
члена орбиты, фильтр диапазона выбирает единственный `k`.

Это позволяет моделировать уже сокращённый диапазон напрямую. Если внешний
этап оставил окно `[a, a+w)`, передайте его в скрипт:

```bash
python3 c7_angle_table_recovery.py --orbits 1000 --seed 20260925 \\
  --interval-start "$a" --interval-size "$w"
```

Для каждого запроса скрипт пересекает шесть кандидатов строки с этим окном и
показывает, в скольких случаях остался один кандидат. Сокращение «в шесть»
относится к числу GLV-представителей/строк таблицы; произвольное короткое
числовое окно не обязано автоматически содержать ровно одного члена каждой
орбиты, поэтому это пересечение следует измерять явно.

Зеркальное отображение `k -> n-k` уже входит в шеститочечную GLV-орбиту:
`P` и `-P` имеют один и тот же `x` и одинаковые значения `Lambda`. Поэтому
его нельзя считать ещё одним независимым выигрышем «в два раза» поверх `6x`.
Его можно использовать как экономию формата таблицы: хранить канонический
представитель `min(k,n-k)`. В режиме `--mirror-canonical` скрипт хранит три
скаляра на строку вместо шести, но возвращает класс по знаку; выбор между
`k` и `n-k` требует внешнего знания диапазона или знака `y`.

Для проверки идеи «якорь + смещение» добавлен
[angle_anchor_experiment.py](angle_anchor_experiment.py): он сравнивает одну
квантованную угловую координату с парой
`(Lambda(P), Lambda(phi(P)))` и измеряет, лежат ли совпавшие скаляры в одном
локальном блоке. Например:

```bash
python3 angle_anchor_experiment.py --range-size 2000 --block-size 100 --bits 8 12 16
```

На пробном окне из 2000 скаляров одна 12-битная координата имела средний
охват ячейки около `9.2%` окна, тогда как пара 12-битных координат — около
`0.08%` и дала `99.9%` одиночных смещений. Это полезно для fingerprint-таблицы,
но не доказывает глобальную формулу `k = anchor + offset`: при расширении
диапазона совпадения могут оказаться далеко друг от друга. Скрипт измеряет
именно это ограничение.

Предположим, что `x_G != 0`, и введём

```text
z = x_P / x_G (mod p).
```

Инвариант принимает вид

```text
L(z) = (1 - beta)^2*z / ((1 - beta*z)*(z - beta)).
```

Эндоморфизм переводит `z` в точки орбиты

```text
z, beta*z, beta^2*z.
```

Положим

```text
S(z) = L(z) + L(beta*z) + L(beta^2*z).
```

После приведения `S(z)` к общему знаменателю его числитель имеет форму

```text
N(z) = z*(beta - 1)^2*(beta*z - 1)^2*
       (beta^2 + beta + 1)*
       (beta^2*z^2 - 2*beta^2*z + 2*beta*z - 2*z + 1).
```

Так как

```text
beta^2 + beta + 1 = 0 (mod p),
```

числитель равен нулю в `F_p`. Следовательно,

```text
S(z) = 0 (mod p)
```

для всех `z`, при которых ненулевыми являются знаменатели трёх орбитальных
значений. Это алгебраическое тождество для выбранного эндоморфизма и функции
`Lambda`.

## Симметричные инварианты орбиты

Для тройки

```text
(L0, L1, L2) = (Lambda(P), Lambda(phi(P)), Lambda(phi^2(P)))
```

рассматриваются симметричные выражения

```text
I2 = L0*L1 + L1*L2 + L2*L0,
I3 = L0*L1*L2,
D  = (L0-L1)^2*(L1-L2)^2*(L2-L0)^2.
```

При `u = z^3` точное сокращение рациональных функций даёт

```text
J(u) = 27*u / (u-1)^2,
I2 = I3 = J(u),
D = -J(u)^2*(4*J(u)+27)  (mod p).
```

Следовательно, `I2`, `I3` и дискриминант `D` не являются тремя независимыми
инвариантами: все они определяются одним значением `J`. Это также следует из
кубического многочлена с корнями `L0`, `L1`, `L2`:

```text
T^3 + I2*T - I3.
```

Его дискриминант равен `-4*I2^3 - 27*I3^2`; после подстановки `I2=I3=J`
получается формула для `D` выше.

Обратное уравнение для `u` имеет вид

```text
J*u^2 - (2*J + 27)*u + J = 0.
```

Его корни суть `u` и `u^-1`. Каждая ветвь соответствует трём `x`-координатам
`z`, `beta*z`, `beta^2*z`; знак `y` удваивает число точек. Поэтому обратный
класс одного симметричного инварианта обычно имеет 6 точек, а если ветвь
`u^-1` также даёт точки кривой -- 12 точек.

Скрипт [symmetric_orbit_invariant_experiment.py](symmetric_orbit_invariant_experiment.py)
проверяет эти равенства и число обратных кандидатов:

```bash
python3 symmetric_orbit_invariant_experiment.py
```

На 100 000 независимых 256-битных скаляров в десяти пакетах по 10 000
(зерна `20260929`--`20261008`) все восемь проверок тождеств и обратного
уравнения дали 0 нарушений. Распределение обратных классов:

| Число точек-кандидатов | Число случаев |
| ---: | ---: |
| 6 | 49 945 |
| 12 | 50 055 |

Таким образом, симметризация трёх значений `Lambda` теряет порядок вершин
орбиты и в среднем расширяет обратный набор кандидатов. Для сокращения
диапазона `k` она не даёт преимущества над уже известным ориентированным
значением `Lambda(P)`.

## Точные фазовые разности

Вещественные углы `2*pi*Lambda_i/p` удобны только для рисунка. Их точным
алгебраическим аналогом служат упорядоченные разности в `F_p`:

```text
d01 = L1-L0,
d12 = L2-L1,
d20 = L0-L2.
```

Так как `L0+L1+L2=0` и `3` обратимо в `F_p`, двух разностей достаточно для
точного восстановления всей упорядоченной тройки:

```text
L0 = -(2*d01+d12)/3,
L1 = L0+d01,
L2 = L1+d12.
```

Скрипт [phase_difference_experiment.py](phase_difference_experiment.py)
сначала обращает `L0` к кандидатам точки, затем оставляет только кандидаты,
чья точная подпись `(d01, d12)` совпадает с исходной.

```bash
python3 phase_difference_experiment.py
```

На 10 000 независимых 256-битных скаляров в двух пакетах по 5 000 (зерна
`20261010` и `20261011`) получено:

| Проверка | Результат |
| --- | ---: |
| Ошибки восстановления `(L0, L1, L2)` из `(d01, d12)` | 0 |
| Исходная `P` среди кандидатов подписи | 10 000 / 10 000 |
| `-P` среди кандидатов подписи | 10 000 / 10 000 |
| Кандидаты из одного `Lambda(P)`: 2 точки | 4 932 |
| Кандидаты из одного `Lambda(P)`: 4 точки | 5 068 |
| Кандидаты после `(d01, d12)`: 2 точки | 10 000 / 10 000 |

Следовательно, точная упорядоченная фазовая подпись устраняет вторую ветвь
по `x`, встречающуюся при обращении одного `Lambda(P)`, и на этой выборке
оставляет только неизбежную пару `P`, `-P`. Это обращение характеристики
публичной точки, а не вычисление дискретного логарифма `k`.

## Угол первого радиуса и площадь

Для первого радиуса треугольника вводится угол

```text
theta(P) = Arg(exp(2*pi*i*Lambda(P)/p)).
```

Его точным ключом в поле служит сам остаток `Lambda(P)`; вещественный угол
используется только для построения окружности. Скрипт
[area_angle_signature_experiment.py](area_angle_signature_experiment.py)
проверяет геометрическую подпись

```text
(theta(P), S(P)),
```

где `S(P)` -- площадь треугольника трёх точек на единичной окружности.
Он сравнивает кандидаты по одной `Lambda(P)` с кандидатами, совпадающими и
по углу первого радиуса, и по площади.

```bash
python3 area_angle_signature_experiment.py
```

На 10 000 независимых 256-битных скаляров в двух пакетах по 5 000 получено:

| Проверка | Результат |
| --- | ---: |
| Повторы `(theta, S)` среди случайных исходных ключей | 0 |
| Одна `x`-координата при фиксированном `theta` | 4 968 |
| Две `x`-координаты при фиксированном `theta` | 5 032 |
| Одна `x`-координата при фиксированных `(theta, S)` | 6 591 |
| Две `x`-координаты при фиксированных `(theta, S)` | 3 409 |

В отдельной точной проверке первых 5 000 ключей все 1 735 оставшихся вторых
`x`-ветвей имели тот же неупорядоченный набор трёх значений `Lambda`.
Следовательно, у них совпадает не только двоичное приближение площади, но и
сами вершины треугольника как множество. Угол вместе с площадью уменьшает
число обратных `x`-кандидатов, но не делает геометрическую подпись строго
инъективной на этой выборке.

## Скалярное тождество

Для канонического скаляра

```text
1 <= k < n,
```

скрипт строит `P = kG` и повторно вычисляет то же равенство. Поскольку
`G` имеет порядок `n`, скаляр определён единственно по модулю `n`; в
каноническом диапазоне это связывает построенную точку с единственным `k`.

## Гипотеза о конечной точке

`TORUS_TURNS = d` является параметром эксперимента. Используемая в скрипте
фазовая параметризация имеет вид

```text
phase(h) = d*h/k.
```

Поэтому в конечной точке `h = k`

```text
phase(k) = d.
```

Состояние "отсутствует при h = k" является граничным правилом модели. Оно
отделено от доказанного орбитального тождества `Lambda`, чтобы не смешивать
эти два утверждения.

## Воспроизведение

Подробный анализ использует только стандартную библиотеку Python:

```bash
python3 w1.py
```

Число образцов и `d` задаются в начале `w1.py`:

```python
SAMPLE_COUNT = 8
TORUS_TURNS = 3
```

Для массового эксперимента необходим пакет `cryptography`:

```bash
python3 -c "from w1 import print_256_bit_experiment_report, run_256_bit_invariant_experiment; print_256_bit_experiment_report(run_256_bit_invariant_experiment(100000, 3))"
```

Массовый режим равномерно выбирает скаляры из интервала

```text
[2^255, n - 1],
```

поэтому каждый скаляр имеет длину ровно 256 бит. Открытые точки вычисляются
нативной реализацией secp256k1 из OpenSSL через `cryptography`; орбита и
значения `Lambda` вычисляются кодом `w1.py`.

## Экспериментальная связь `d = f(k)`

Отдельный скрипт [d_from_height_experiment.py](d_from_height_experiment.py)
задаёт воспроизводимую кандидатную связь между высотой и числом оборотов:

```text
d(k) = 1 + (Lambda(kG) mod TURN_MODULUS).
```

При известном `k` скрипт повторно строит `P = kG`, вычисляет `Lambda(P)` и
получает то же значение `d`. По умолчанию `TURN_MODULUS = 256`, поэтому
`d` принимает значения от 1 до 256.

Запуск:

```bash
python3 d_from_height_experiment.py
```

Скрипт использует 1 000 случайных скаляров длиной ровно 256 бит и считает:

| Проверка | Результат |
| --- | --- |
| `Lambda(kG)` определён | Проверяется для каждого `k` |
| Повторное вычисление `d(k)` | Должно вернуть исходное `d` |
| `phase(k) = d(k)` | Проверяется точно через рациональную арифметику |

## Эксперимент с наблюдаемым периодом орбиты

Скрипт [orbit_period_experiment.py](orbit_period_experiment.py) вводит
независимо вычисляемое наблюдаемое значение

```text
d_observed(P) = min {m > 0 : phi^m(P) = P}.
```

Оно сравнивается с двумя кандидатными функциями:

```text
d_constant(k) = 3
d_lambda(k) = 1 + (Lambda(kG) mod 256).
```

Запуск полного эксперимента:

```bash
python3 orbit_period_experiment.py
```

На 100 000 независимых 256-битных скаляров, в четырёх пакетах по 25 000,
получены следующие результаты:

| Проверка | Результат |
| --- | ---: |
| Некорректные точки кривой | 0 |
| Неопределённый период орбиты | 0 |
| `d_observed != 3` | 0 |
| Совпадения `d_constant = d_observed` | 100 000 / 100 000 |
| Неопределённые значения `Lambda` | 0 |
| Совпадения `d_lambda = d_observed` | 422 / 100 000 |

Если число оборотов `d` отождествляется с периодом эндоморфизмной орбиты,
эксперимент подтверждает `d = 3` для данной выборки. Кандидатная связь через
остаток `Lambda mod 256` с наблюдаемым периодом не согласуется.

## Обращение `Lambda` к кандидатам точки

Скрипт [2edcl.py](2edcl.py) исследует обратную задачу для инварианта
`Lambda(P)`. При известном `Lambda(P)` он выводит квадратное уравнение для
`x(P)`, находит его корни в `F_p`, строит все точки кривой с этими
координатами и оставляет только точки, дающие исходное значение `Lambda`.

Для каждого фиксированного `Lambda` квадратное уравнение даёт не более двух
значений `x`; следовательно, на secp256k1 набор кандидатов содержит не более
четырёх точек `P`.

```bash
python3 2edcl.py
```

Полный эксперимент выполнен на 100 000 независимых скаляров длиной ровно
256 бит. Публичные точки `P = kG` строились нативной реализацией secp256k1
из OpenSSL через `cryptography`.

| Проверка | Результат |
| --- | ---: |
| Неопределённые значения `Lambda` | 0 |
| Исходная `P` отсутствует среди кандидатов | 0 |
| Исходная `P` присутствует среди кандидатов | 100 000 / 100 000 |
| Наборы из двух точек-кандидатов | 49 846 |
| Наборы из четырёх точек-кандидатов | 50 154 |

Суммарное время десяти пакетов по 10 000 точек составило 200.29 с.

## Проверка утечки битов скаляра через инварианты

Скрипт [invariant_leakage_experiment.py](invariant_leakage_experiment.py)
проверяет, уменьшают ли остатки орбитальной тройки инвариантов диапазон
возможных значений `k`. Для каждого 256-битного скаляра используются

```text
(Lambda(P), Lambda(phi(P)), Lambda(phi^2(P))) mod 2^b
```

как признаки для предсказания `k mod 2^b`. Первая половина выборки строит
таблицу наиболее частых соответствий, вторая независимая половина измеряет
точность. Это исключает оценку на тех же данных, на которых строился
предиктор.

```bash
python3 invariant_leakage_experiment.py
```

Проверочный прогон на 20 000 256-битных скалярах с 10 000 независимых
тестовых примеров дал следующие результаты:

| `2^b` | Предсказание `k mod 2^b` | Случайный базис |
| ---: | ---: | ---: |
| 2 | 50.22% | 50.00% |
| 4 | 25.13% | 25.00% |
| 8 | 12.46% | 12.50% |
| 16 | 6.28% | 6.25% |
| 32 | 3.10% | 3.125% |
| 64 | 1.68% | 1.5625% |

В этой проверке тройка остатков `Lambda` не предсказывает младшие 1--6 бит

## Фазовый тор и площади треугольников `Lambda`

Скрипт [lambda_circle_triangle_experiment.py](lambda_circle_triangle_experiment.py)
строит геометрическую визуализацию точных значений `Lambda` из `w1.py`.
Для остатка `a` в `F_p` явно задаётся отображение на единичную окружность

```text
chi(a) = exp(2*pi*i*a/p),  0 <= a < p.
```

Для тройки орбиты

```text
(L0, L1, L2) = (Lambda(P), Lambda(phi(P)), Lambda(phi^2(P)))
```

из доказанного тождества `L0 + L1 + L2 = 0 (mod p)` следует

```text
chi(L0) * chi(L1) * chi(L2) = 1.
```

Следовательно, тройка фаз лежит на фазовом торе

```text
T^2 = { (u0, u1, u2) in (S^1)^3 : u0*u1*u2 = 1 }.
```

Точки `chi(L0)`, `chi(L1)`, `chi(L2)` являются вершинами вписанного в
единичную окружность треугольника. Его площадь вычисляется формулой
Гаусса (shoelace). Скрипт также создаёт [lambda_phase_torus.svg](lambda_phase_torus.svg)
с одним представительным треугольником и точкой на параметрическом торе.

```bash
python3 lambda_circle_triangle_experiment.py
```

Важно: `chi` является соглашением для перехода от конечного поля к
евклидовой картинке. Площадь -- численная характеристика этой выбранной
модели, а не канонический инвариант эллиптической кривой.

Проверка на 100 000 независимых 256-битных скаляров в пяти пакетах по
20 000 (зерна `20260917`--`20260921`) дала:

| Проверка | Результат |
| --- | ---: |
| Неопределённые тройки `Lambda` | 0 |
| Нарушения `L0 + L1 + L2 = 0 (mod p)` | 0 |
| Повторы точной неупорядоченной тройки `(L0, L1, L2)` | 0 |
| Повторы площади после округления до 12 знаков | 0 |
| Минимальный численный разрыв площадей | `8.769693261509448e-11` |
| Минимальная площадь | `8.995016e-09` |
| Максимальная площадь | `1.299030779499380` |
| Средняя площадь | `0.475492901342204` |

Отсутствие повторов в этой выборке не доказывает инъективность площади
относительно `k`; оно лишь не обнаруживает коллизий в выбранном объёме и
при указанной численной точности.

## Табличный поиск и точная коллизия

Скрипт [area_lookup_table_experiment.py](area_lookup_table_experiment.py)
проверяет идею восстановления скаляра по заранее вычисленной таблице
площадей. Для каждого скаляра `k` в таблицу намеренно добавляется пара

```text
k, n-k.
```

Если `P = kG`, то `(n-k)G = -P`. Поэтому

```text
x(-P) = x(P),
Lambda(-P) = Lambda(P),
Lambda(phi^i(-P)) = Lambda(phi^i(P)),  i = 0, 1, 2.
```

Тройка вершин на окружности и её площадь у `k` и `n-k` совпадают. Следует
точное равенство для выбранной геометрической модели:

```text
A(k) = A(n-k).
```

```bash
python3 area_lookup_table_experiment.py
```

На 100 000 табличных ключах, составленных из 50 000 пар `k, n-k`, получено:

| Проверка | Результат |
| --- | ---: |
| Несовпадения точной тройки `Lambda` внутри пар | 0 |
| Несовпадения ключа площади внутри пар | 0 |
| Поисков по площади, содержащих исходный скаляр | 100 000 / 100 000 |
| Поисков с двумя кандидатами | 100 000 / 100 000 |
| Поисков с единственным кандидатом | 0 |

Следовательно, таблица площадей способна вернуть класс кандидатов, но не
может однозначно восстановить произвольный `k` в группе secp256k1. Если
известен внешний диапазон, исключающий один из двух скаляров, он может снять
эту конкретную неоднозначность; это дополнительное знание, а не информация,
полученная из площади.

## Отношение площадей для `P` и `2P`

Скрипт [area_ratio_experiment.py](area_ratio_experiment.py) исследует
нормированное отношение площадей

```text
rho(k) = S(2P) / (S(P) + S(2P)),  P = kG.
```

При ненулевых площадях из `rho` восстанавливается обычное отношение:

```text
S(2P) / S(P) = rho / (1-rho).
```

Первая половина выборки строит для 256 интервалов `rho` наиболее частое
значение `k mod 2^b`; вторая половина независимо проверяет предсказание.

```bash
python3 area_ratio_experiment.py
```

Пилот на 10 000 256-битных скаляров (5 000 для обучения и 5 000 для
проверки, зерно `20260925`) дал:

| `2^b` | Точность по `rho` | Случайный базис |
| ---: | ---: | ---: |
| 2 | 50.64% | 50.00% |
| 4 | 24.78% | 25.00% |
| 8 | 12.52% | 12.50% |
| 16 | 5.92% | 6.25% |
| 32 | 2.90% | 3.125% |
| 64 | 1.44% | 1.5625% |

На этом объёме конкретное отношение площадей `S(2P)/S(P)` не обнаруживает
предсказуемой связи с младшими 1--6 битами `k`. Это не является общим
доказательством отсутствия отношений для других кратных `mP` или других
функций от площадей.

## Совместные отношения для `2P`, `3P`, `5P`

Скрипт [area_multi_ratio_experiment.py](area_multi_ratio_experiment.py)
расширяет проверку на вектор

Каждая координата квантуется в 8 интервалов, поэтому совместный признак

соответствия строятся на первой половине данных и проверяются на второй.

```bash
python3 area_multi_ratio_experiment.py
```

Пилот на 6 000 256-битных скаляров (3 000 для обучения и 3 000 для
проверки, зерно `20260926`) дал покрытие ранее встречавшимися ячейками
`97.87%` и следующие результаты:

| `2^b` | Точность по `(rho_2, rho_3, rho_5)` | Случайный базис |
| ---: | ---: | ---: |
| 2 | 50.30% | 50.00% |
| 4 | 24.03% | 25.00% |
| 8 | 11.30% | 12.50% |
| 16 | 5.87% | 6.25% |
| 32 | 2.77% | 3.125% |

В этой дискретизации совместное использование трёх отношений не даёт
наблюдаемого предсказания младших битов `k` сверх случайного уровня.

## Смещение площади по высоте скаляра

Скрипт [area_shift_experiment.py](area_shift_experiment.py) проверяет не
предсказание битов, а изменение распределения площади `S(kG)` при изменении
высоты `k`. Интервал 256-битных скаляров `[2^255, n)` делится на восемь
равных полос; для каждой измеряются средняя площадь, стандартная ошибка и
двухвыборочное расстояние Колмогорова--Смирнова относительно остальных
полос.

```bash
python3 area_shift_experiment.py
```

На 16 000 скаляров (2 000 на полосу, зерно `20260927`) получены:

| Показатель | Результат |
| --- | ---: |
| Средняя площадь по выборке | `0.476723145869` |
| Стандартное отклонение площади | `0.382782155276` |
| Корреляция `corr(k, S(kG))` после нормирования `k` | `-0.00448743` |
| Наибольшее KS-расстояние полосы к остальным | `0.03878571` |

Наибольшее исходное расстояние наблюдалось у полосы `2/8`. Чтобы не принять
случайный максимум среди восьми сравнений за эффект, он отдельно проверяется
скриптом [area_shift_confirmation.py](area_shift_confirmation.py) на новой
выборке без поиска новых полос:

```bash
python3 area_shift_confirmation.py
```

Проверка на 20 000 новых скаляров (10 000 в полосе `2/8` и 10 000 в смеси
остальных полос, зерно `20260928`) дала `KS = 0.01160000`, асимптотическую
оценку `p = 0.50934684` и сдвиг среднего `+0.000724306009` при `z = 0.134119`.
Таким образом, исходный максимум KS не подтвердился как устойчивое смещение
площади по высоте `k`.

## Область применимости

Формальный вывод устанавливает орбитальное тождество для `Lambda` при
указанных условиях области определения. Прогон 100 000 образцов служит
проверкой воспроизводимости реализации: он подтверждает согласованность кода
с тождеством, а математическим обоснованием является приведённый выше вывод.
